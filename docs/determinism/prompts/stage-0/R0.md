# R0 — Stage 0 gate review (the adaptive core)

## Context (cold start)

You are the Stage 0 review gate. Stage 0 built the measurement harness (S0.3), the divergence
classifier (S0.4), the corpus (S0.5), the metric (S0.6), and — most importantly — the stage
checkpoint/replay capability (S0.7b). Your job is to turn what those tasks *learned* into a
revised plan and into the ready-to-dispatch prompts for Stage 1. Read
`docs/determinism/ORCHESTRATION.md` §"Stage-gate review" — it is your spec.

The plan beyond Stage 0 was deliberately left as guesses (`stage_placeholders` in
`tasks.yaml`). You now have real data; replace guesses with reality.

## The decisions Stage 0's data should drive

- **The category ranking (from S0.4/S0.6)** tells you which stages matter. If `path`/
  `timestamp` dominate, Stage 1 is high-yield and easy. If `id-renumber`/`offset-shift`
  dominate, the leverage is Stage 3 (analysis) — consider starting S3.1 early (it only needs
  S0.7b).
- **S0.7b's key finding** — *does the universe→link tail diverge given a frozen reachable
  set?* If NO, Stage 2 is small (the tail is already deterministic) and the whole problem is
  Stage 3. If YES, Stage 2 has real work and you must scope it from the S2.1 audit surface.
- **S0.1's gap report** tells you which Stage 1/2 fixes already exist (drop those tasks) and
  which surfaces are uncovered (add tasks).

## Steps

1. Ingest every `artefacts/handbacks/S0.*.yaml` and skim the deliverables.
2. Write `reviews/stage-0.review.md` from `_TEMPLATE.review.md`: did Stage 0 meet its exit
   criteria; what is now known; what surprised us.
3. Write `reviews/stage-0.review.yaml` from `_TEMPLATE.review.yaml` (schema:
   `schema/review.schema.json`): `plan_changes` (add/modify/drop/reorder on task ids with
   rationale), `risks_discovered`, `decision`, `next_stage_prompts`, `metric_snapshot`.
4. Apply the `plan_changes` to `tasks.yaml`: replace the `stage: 1` placeholder with concrete
   `S1.x` tasks (and adjust later stages if the data demands). Never renumber existing ids;
   `drop` + `add`. Re-validate `tasks.yaml` against `schema/tasks.schema.json`.
5. Generate `prompts/stage-1/S1.x.md` for each Stage 1 task, following the structure of the
   Stage 0 prompts exactly (frontmatter per `schema/prompt.schema.json`; Context / Objective /
   Steps / Definition of done / Handback). Each must be self-contained for a cold-start agent.
6. Generate `prompts/stage-1/_index.yaml` (same shape as `prompts/stage-0/_index.yaml`).
7. Set `decision`. If Stage 0 revealed the problem is *entirely* Stage 3 (tail already
   deterministic), say so and scope Stage 2 down to a verification-only task — do not invent
   busywork.

## Definition of done

- `reviews/stage-0.review.{md,yaml}` exist and are schema-valid.
- `tasks.yaml` revised + re-validated; Stage 1 is concrete, prompt-backed tasks.
- `prompts/stage-1/*.md` + `_index.yaml` exist, schema-valid, self-contained.
- `decision` recorded (`proceed`/`replan`/`halt`).

## Note

You are the *only* task permitted to modify downstream tasks or write next-stage prompts.
Keep the same artefact conventions so the orchestrator and future gates (R1…R5) stay uniform.
