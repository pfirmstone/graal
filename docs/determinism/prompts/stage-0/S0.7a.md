# S0.7a — Design stage checkpoint/replay

## Context (cold start)

This is the single most important enabler in the whole program. Native Image nondeterminism
at any stage smears across all downstream stages (a ±45-method analysis wobble renumbers
every type id and shifts field offsets across the binary), which makes "the image is
nondeterministic" feel like one huge problem. **Checkpoint/replay** decomposes it: freeze the
output of stage N once, run stage N+1 twice from that identical frozen input, and any
remaining divergence is provably introduced *by stage N+1 alone*. That converts one
intractable problem into N independently-testable sub-problems and is what makes Stages 2 and
3 tractable.

The pipeline: `inputs → points-to analysis → universe build → heap/type/field layout →
compile → link → image`. The highest-value checkpoint is **after points-to analysis / universe
build** (so Stage 2 can prove the universe→link tail is deterministic given a frozen
reachable set, isolating the wobble to the analysis itself in Stage 3).

## Objective

A decisive ADR specifying, for each viable checkpoint boundary:

1. **What to serialize** to fully determine the next stage (e.g. the reachable
   method/type/field set + their assigned ids/offsets + whatever the universe build consumes).
2. **How to serialize deterministically** (the checkpoint itself must be canonical — sort by
   stable keys like `getUniqueShortName`).
3. **The replay entry point** — how to start a build from the frozen checkpoint instead of
   re-running analysis (a new `-H:` option / mx hook).
4. **Feasibility & risk** — how much hosted state is reachable-but-not-easily-serializable;
   where a full freeze is impractical and a *partial* freeze (or a record-and-compare instead
   of replay) is the fallback.

## What to study

- `UniverseBuilder` (how `HostedType`/`HostedMethod`/`HostedField` and type ids / field
  layout are produced from analysis results) and `TypeCheckBuilder` (type-id assignment is
  deterministic *given* a stable type set — confirm).
- The analysis universe (`AnalysisUniverse`, `aUniverse.getTypes()/getMethods()/getFields()`)
  as the natural freeze point.
- Any existing image-layer / persistence machinery (search `layer`, `persist`, `Serializ`)
  that could be reused rather than built from scratch.

## Deliverable

`adr-checkpoint-replay.md`: the chosen primary checkpoint boundary, the serialize/replay
design, a ranked list of boundaries (feasible now / later / impractical), and the fallback
("record-and-compare" where true replay is infeasible).

## Definition of done

- At least the post-analysis boundary has a concrete, implementable design (input set, format,
  replay entry point).
- Risks and fallbacks named; S0.7b can implement without redesign.
