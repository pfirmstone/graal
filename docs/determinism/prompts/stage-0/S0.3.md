# S0.3 — Implement the build-twice-and-diff harness

## Context (cold start)

Implement the harness designed in `artefacts/stage-0/adr-harness.md`. A working LLVM-only
prototype exists in `substratevm/mx.substratevm/mx_substratevm.py`
(`llvm_backend_determinism_test` and helpers). Generalize it per the ADR into a
backend-agnostic command (default backend primary), without breaking the existing one.

## Objective

`mx native-image-determinism-test [--backend default|llvm] [--app NAME] [--keep-output]`
that builds the app twice into independent temp dirs, hashes the ADR's stage-boundary
artefacts, diffs them, and reports per-stage divergence. Plus a CI workflow.

## Steps

1. Read the ADR; implement exactly its stage boundaries and artefact layout.
2. Factor shared helpers out of the existing LLVM command (`_sha256_of_file`,
   `_diff_hashes`, the run-a/run-b scaffolding) rather than duplicating; keep
   `llvm-backend-determinism-test` green.
3. For the default backend: build the app twice with `-H:TempDirectory=<dir>`, collect the
   SVM-* object file(s) and the final binary (the ADR lists exactly what); hash + diff.
4. Sort all file lists before hashing so the harness is itself deterministic.
5. Add `.github/workflows/native-image-determinism.yml` modelled on
   `llvm-backend-determinism.yml` (build GraalVM, run the command, `always()` artefact
   upload with `if-no-files-found: warn`). Validate the YAML before committing (a single
   duplicate key fails the whole workflow — see git history).
6. Leave classification to S0.4; this task only needs to *detect and locate* divergence.

## Constraints / gotchas

- You cannot build Native Image locally on Windows for the LLVM backend; the default
  backend builds via the standard GraalVM build. Rely on CI for end-to-end validation —
  budget ~3 iterations and make each CI run maximally informative.
- Do not regress `mx llvm-backend-determinism-test`; run it (in CI) to confirm.
- `svmbuild_dir(suite)` resolves to `substratevm/mxbuild/jdk<ver>/svmbuild`, not
  `substratevm/svmbuild` — get upload globs right (past bug).

## Definition of done

- The command exists, runs in CI, and reports per-stage divergence for >=1 corpus app.
- Existing LLVM gate still passes its own job.
- Workflow YAML parses (no duplicate keys).
