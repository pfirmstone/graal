# S0.1 — Inventory existing determinism machinery

## Context (you are starting cold)

You are the first task in a program to make GraalVM Native Image byte-reproducible.
A prior investigation fixed the LLVM backend's own nondeterminism and proved the residual
is upstream: the points-to analysis yields a slightly different reachable method/type/field
set each build, which renumbers type ids and shifts field offsets across the whole image.
Read `docs/determinism/README.md` for the full framing.

Native Image already contains a fair amount of determinism machinery. Before anyone fixes
anything, we need a precise map of **what already exists** and **where the gaps are**, so the
program is "close the gaps" rather than "start from zero." That map is your deliverable.

## Objective

Produce a ranked inventory of existing determinism mechanisms and uncovered surfaces.

## Where to look (seed list — extend it)

Use Grep/Glob across `substratevm/src/` and `compiler/src/`. Known starting points:

- **Deterministic comparators / sorts:** `HostedUniverse.TYPE_COMPARATOR`,
  `METHOD_COMPARATOR`, `FIELD_COMPARATOR_RELAXED`, `TypeCheckBuilder.TYPECHECK_COMPARATOR`,
  `NativeImageHeap.DETERMINISTIC_FIELD_COMPARATOR`,
  `NativeImageCodeCache.deterministicCompilationUnitOrderForConstantLayout`,
  `SortByMethodNameCodeSectionLayouter`. (search: `Comparator`, `getUniqueShortName`,
  `deterministic`, `sorted(`)
- **Economic / ordered collections & markers:** `EconomicMap`, `EconomicSet`,
  `LinkedHashMap`, and the `noEconomicSet(streaming)` style comments. (search:
  `noEconomicSet`, `EconomicMap`, `new HashMap`, `new HashSet`)
- **Time / environment:** `TimeUtils.currentTimeMillis`, `SOURCE_DATE_EPOCH`,
  `TemporaryBuildDirectoryProviderImpl` (the `SVM-<currentTimeMillis>` temp dir),
  object-file timestamp handling (`MachOObjectFile` DylibCommand `timestamp`, `ELF*`,
  `PECoff*`). (search: `currentTimeMillis`, `SOURCE_DATE_EPOCH`, `timestamp`)
- **Identity / addresses / random:** (search: `identityHashCode`, `System.identityHashCode`,
  `Math.random`, `new Random`, `UUID`)

## Steps

1. Read the two `reads` files for framing and the classifier taxonomy.
2. Run the searches above (and follow-ups they suggest) across the hosted (build-time)
   code. Hosted code is what shapes image bytes; runtime code generally does not.
3. For each hit, record: mechanism/site (`file:line`), category
   (`order|time|path|identity|address|other`), whether it is a *protection*
   (already deterministic) or a *gap* (potential nondeterminism reaching output), and a
   one-line note.
4. Rank gaps by likely reproducibility impact (does it plausibly reach image bytes?).

## Deliverable

`artefacts/stage-0/determinism-inventory.md` with two tables — **Protections** and
**Gaps (ranked)** — plus a short "biggest unknowns" section.

## Definition of done

- Both tables present, every row has `file:line` + category.
- Gaps ranked; top 10 each have a one-line "why it might reach output."
- No code changes (this is read-only).
