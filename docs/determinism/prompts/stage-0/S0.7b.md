# S0.7b — Implement stage checkpoint/replay

## Context (cold start)

Implement the design in `artefacts/stage-0/adr-checkpoint-replay.md`. This is the enabler
that lets Stage 2 prove "universe→link is deterministic given a frozen reachable set" and lets
Stage 3 isolate the analysis wobble. Treat correctness of the *freeze* as paramount: if the
checkpoint silently drops state, replayed builds will look falsely nondeterministic (or falsely
deterministic), which would mislead every downstream stage.

## Objective

A `-H:` option (or mx hook, per the ADR) that:
1. **Capture mode:** runs analysis once, serializes the chosen checkpoint canonically to a
   file.
2. **Replay mode:** starts a build from the checkpoint file, skipping re-analysis, and runs the
   downstream stages.
3. Integrate with the harness (S0.3): a `--from-checkpoint` path that builds the *downstream*
   stages twice from one checkpoint and diffs — so divergence is attributable to those stages
   only.

## Steps

1. Implement capture: serialize the post-analysis state the ADR specifies, sorted by stable
   keys (canonical bytes — verify the checkpoint file itself is reproducible across two capture
   runs *of the same analysis result*, modulo the analysis wobble; if the checkpoint differs
   only where the analysis set differs, capture is correct).
2. Implement replay: reconstruct the downstream entry state from the checkpoint; bypass
   analysis.
3. Add the harness mode; run on one corpus app in CI: capture once, replay twice, diff.
4. If full replay proves impractical at some boundary (per ADR risk), implement the
   **record-and-compare** fallback there (record the stage's inputs; compare across two normal
   builds to detect whether the *input* or the *stage* differs) and document the limitation.

## Constraints / gotchas

- **Correctness over completeness.** A partial-but-sound checkpoint (with documented
  coverage) beats a full-but-leaky one. State precisely what the checkpoint does and does not
  freeze.
- Expect ~4 CI iterations; each capture/replay bug is subtle. Make capture emit a manifest of
  exactly what it serialized so replay mismatches are debuggable from artefacts.
- Do not perturb the normal (non-checkpoint) build path.

## Definition of done

- Capture + replay work for the post-analysis boundary on >=1 corpus app in CI.
- Harness `--from-checkpoint` reports stage-local divergence.
- `checkpoint-replay-notes.md` documents coverage, fallbacks, and known gaps.
