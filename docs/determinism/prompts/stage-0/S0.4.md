# S0.4 — Divergence classifier

## Context (cold start)

The harness (S0.3) detects *that* artefacts differ. This task explains *why* by classifying
each divergence into a category, so the metric (S0.6) and the review gates can target the
right stage. A proven classifier already exists for LLVM IR:
`substratevm/docs/llvm-backend-determinism-classifier-spec.md` — its token-rule
(differences are "operand-constant-only" vs "structural") and whitelist approach are
directly reusable. Extend it from IR to machine code (objdump) and to the category taxonomy.

## Category taxonomy (fixed; extend only via a review gate)

`timestamp` · `path` (embedded build paths) · `order` (collection-iteration order) ·
`id-renumber` (type ids / patchpoint ids) · `offset-shift` (field/layout offsets) ·
`address` (absolute addresses) · `other` (escalate).

## Objective

Given two artefacts the harness flagged as differing, emit `(stage, category, evidence)`
for each divergence, and an aggregate per-(stage,category) count.

## Steps

1. Reuse the spec's line-pair token classifier for LLVM IR (`llvm-dis` diffs). The unit-test
   vectors in the spec MUST pass (port them into a local self-test).
2. For machine code (default backend), disassemble with `llvm-objdump`/`objdump`
   (`_objdump_diff` already exists) and classify by pattern:
   - `id-renumber`: `(typeId - start) <u range` shape — `and …, 0xffff` then a changed
     `leal -0xN` / `cmpl 0xN` immediate. (Statepoint ids are LLVM-only; the spec covers them.)
   - `offset-shift`: changed displacement in `mov OFF(%reg)` / GEP, structure otherwise equal.
   - `path`/`timestamp`: changed strings/dates in data sections.
   - `order`: same instructions present but reordered (set-equal, sequence-unequal).
   - else `other`.
3. Map each divergence to a pipeline `stage` using the artefact it came from (the harness
   tags artefacts by stage).
4. Emit `classifier-report.example.md` for one corpus app: the per-(stage,category) table +
   a few evidence snippets.

## Constraints / gotchas

- Prefer the **whitelist / invert-the-problem** design from the spec: do not try to
  semantically resolve every constant; classify by line/instruction *shape*. Mark anything
  unrecognized as `other` (conservative) rather than guessing.
- `llvm-dis`/`objdump` may be absent; degrade gracefully (report `category: unknown`,
  don't crash) and note it.

## Definition of done

- Local self-test (spec vectors + a few objdump cases) passes via `python -m`.
- One corpus app's report shows a populated per-(stage,category) table in CI.
